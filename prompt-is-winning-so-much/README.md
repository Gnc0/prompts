# prompt-is-winning-so-much

图式闭合提示词生成与哲学对话的实验场。这里存放的不是一次性提示词，而是**可复用的提示词技能**（skill）——每个子目录是一个技能，描述一种可被反复调用的提示词工作方式，通常对应一次真实的提示词打磨过程。

## 使用方式：两级路由

- **一级路由**（本 README）：按场景找到技能目录。
- **二级路由**（各技能目录内的 `SKILL.md`）：技能内部若有多个版本或子技能，由 `SKILL.md` 决定选哪个文件。

`SKILL.md` 的 frontmatter `name` 是技能的唯一标识，`description` 是路由线索（什么场景用本技能）。

## 技能详解

### 抽象分析者（abstraction-analyst）

在回应用户之前先完成一次理解，并把理解写成一份记录。先定义六个术语（需求、话题结构等），按定义使用；理解失败有明确的处置表。适用于：模糊或宽泛的提问、进入新话题、收到背景材料、对话中需求变化、回应屡屡落空需要诊断。

### 分析哲学散文（analytic-philosophy-prose）

全部规则从一个原则推出：**散文是陈述命题的工具，不是产生效果的媒介。** 三条派生原理：清晰是伦理规范；可证伪性最大化；陈述方式应使分歧点能被精确定位。适用于要求期刊风格写作、形式化定义与严格论证、去除修辞与术语堆砌、评估文本是否达标。

### 哲学对话者（philosophy-interlocutor）

与用户一起推进哲学命题，而不是向用户表演解释力。所有规则来自用户在真实对话中的逐条纠正，每条规则对应一次实际犯过的错。核心约束：

- 不使用任何排版装饰（不加粗、不做标题、不用列表符号）；
- 结论放在最后，先呈现场景与事实再逐步推导；
- 每一步推导都要能被用户击中：枚举先于选择、判据先于结论；
- 概念从现象自身的结构里长出来，不拆外部理论零件拼装；
- 生造术语后禁止靠拆字解释，必须用独立于该术语的方式指认现象；
- 被纠正后先确认理解对了再继续。

适用于：哲学概念构造、命题论证、论文观点打磨、术语命名，以及用户纠正对话方式之后。

### 哲学探索者（philosophy-explorer）

定位是思想编辑而非资料整理员或合规审查员——产出帮助用户看到：当前最可能成立的判断、哪些冲突值得继续、哪些只是噪声、下一步该做什么。两个版本：

| 版本 | 文件 | 适用场景 |
|------|------|----------|
| 基础版 | `philosophy-explorer-base.md` | 规则刚性、构成性强：每轮必须形成暂定结论、每个重要问题必须说明赌注。适合材料充分、需要强判断推进的场景 |
| 规约版 | `philosophy-explorer-regulation.md` | 调节性软化：允许"赌注待明确""本轮无高置信结论"等弹性条款。适合材料稀薄、需要容错的场景 |

### 图式匹配者（schema-matcher）

把六对图式从诊断工具转为运行时行为调节器：每次回复前判断用户需求在六根图式轴上的位置，让回答的抽象层级、覆盖分布、关系取向、选择取舍、表征密度与模态姿态逐一落在对应位置，并把判断显式输出为 `<think_schema>` 块。用于消除"答非所问""正确但无用""合理但不真"等认知姿态错配。`eval/` 下有评测脚手架，`EXPERIENCE-schema-matcher.md` 记录了本技能的打磨过程与可复用流程。

### 通用提示词生成（general-prompt）

七层图式闭合方法论，将领域提示词需求映射为可执行的多层闭合约束系统。两个版本：

| 版本 | 文件 | 适用场景 |
|------|------|----------|
| 基础版 | `general-prompt-base.md` | 七层闭合的完整流程，Layer 4 认识论分层用简要五分类概述。适合不需要精细区分推测处理权限的场景 |
| 判官版 | `general-prompt-judge.md` | 在基础版上强化 Layer 4：六类标记体系 + 独立「自决规则」块，显式区分「推测·可自决」与「推测·强确定性」。半角标点 + 术语加引号 |

### 游戏设计（designer）

游戏设计相关技能路由，按需求在三个子技能之间选择：

| 子技能 | 文件 | 适用场景 |
|--------|------|----------|
| 文案策划 | `content-designer.md` | 已有玩法/题材/世界观/美术方向，需要判断如何包装并落到系统与美术 |
| MDA 需求拆解 | `sd-mda.md` | 功能想法模糊，需要先拆解为「体验目标 + 玩家行为」，供策划案撰写 |
| 系统策划案撰写 | `sd-writer.md` | 已有 MDA 拆解或规则草案，需要转化为结构化系统规则文档 |

## 约定

- 每个技能目录独立可读：进入目录后以 `SKILL.md` 为准。
- 技能是提示词，不是代码；修改后无需构建，直接生效。
- 新增技能：新建 `prompt-is-winning-so-much/<skill-name>/SKILL.md`，并在本 README 的技能清单中登记。
