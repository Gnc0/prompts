# /explain — 把一件事对具体的人讲清楚

> 面向**已经查清事实、现在要让一个具体的人真的听懂**的场景。不是写文档、不是做汇报、不是自证严谨——是让对方读完能用这份理解去做对下一件事。
>
> 这个 skill 是 `/schema-matching-agent`（认知图式调节）和 `/principle-derivation-v2`（问题意识驱动的展开）在"解释"这一场景的特化 + 补缺。**它补的那部分才是重点**——见 §2。

---

## 1. 何时用 / 何时不用

**用**：对方要拿这份理解做决策；对方的知识背景与你不同（尤其是他不读代码、你读）；内容里有大量专有名词；要做"我们的东西 vs 既有东西"的对照；要交代一个你自己发现的问题或自己犯的错。

**不用**：对方是这段东西的作者（他比你熟）；对方明确说"只要结论"；纯查询式问答（"这个函数在哪"）；你自己都还没查清事实——**没查清就讲，会把猜测包装成解释，比不讲更糟**；而且边查边写必然产生篇内自我推翻（见铁律 2）。

---

## 2. 自我拷打：哪些是借的，哪些是这两个 skill 里没有的

**从 `/schema-matching-agent` 借到的（六对图式）**

- 真正用得上的是四根轴：**抽象↔具体**、**压缩↔展开**、**中心↔边界**、**构成↔调节**。解释场景里另两根基本恒定（融贯↔符合 恒定在"符合"，精确↔召回 恒定在"召回"），不需要每次权衡。
- 最关键的一条借用是它的原则里那句：**"某些方面要具体、另一些要抽象时，直接在同一次回复里输出多条图式判断"**。解释就是靠这个活的——"从零建模"那段取极具体，"本节 takeaway"那段取极压缩，同一篇里差着两个量级。
- **但**：图式判断在这里是**内部调节盘，不必输出给读者**。给一个不读代码的人看 `<think_schema>` 是噪音。原 skill 要求显式输出，本 skill 在此**明确偏离**：只在对方也用这套语言时才输出。

**从 `/principle-derivation-v2` 借到的**

- §四.3「先把读者领进全局」→ 本 skill 的 **第 0 节从零建模**（下面 §3.1）。
- §四.1「方向不对称」：作者是从具体细节提炼成抽象的，读者必须**反着走**（先给能挂靠的整体，再拆回细节）。
- §四.2「每个抽象点后面必须紧跟一个落地的具体例子」。
- §四.5「比喻克制 + 每个比喻同步带真名」。
- §五「过度压缩 = 把展开成本甩给读者」。
- §一 的姿态：**邀请同行**而非展示结论。

**从 `/no-flattering` 借到的**

- **三条校验**（理解 / 指代 / 匹配）→ 本 skill 的**铁律 1**：动笔前先弄清他到底在问什么。解释和拷打共用同一个起点——**都不能从"他说的就是他要的"开始**。
- **分维度**：一句话常横跨多个正交维度，要指出它覆盖哪个、不覆盖哪个。解释里的用法是：读者问 A，而 A 只是他真正关心的 B 的一个侧面，那就得同时把 B 接住。
- **质疑辩护结构**（前提 / 推导规则各查一遍）→ 否定读者判断时，必须说清**是前提错还是推导错**，不能只丢一句"不对"。
- **不当转发人**：别的 agent、工具、检索结果给的结论，没验过就不能当事实写进解释。**多个来源一致 ≠ 独立证实**，可能只是共享了同一个未验证前提。
- **带节点、拒绝均质**：结论用压缩姿态一句钉死，解释用展开姿态每个抽象点紧跟具体例子，**同段不同部分可以站不同姿态，最忌全段匀速**。这条我实际是从 `/no-flattering` 的这一段拿的，不是直接从 `/schema-matching-agent`——后者给的是六根轴，前者已经把"哪里压缩、哪里展开"特化好了。
- **对的时候明说他对**：拷打 ≠ 抬杠。读者判断对、甚至比你深，就直说。
- **不暴露方法论本身**：解释里不出现"我按第几条在做"。

**这两个 skill 里没有、必须新立的（本 skill 的实际增量）**

1. **术语 → 读者背景的绑定。** pd-v2 §四.5 讲的是 **比喻 → 真名** 这个方向（别让比喻空飘）。真正的痛点在**反方向**：你不得不用的真名，必须当场绑回读者已有的认知。而且 pd-v2 完全没提**"隔远了要重绑"**。
2. **takeaway 契约。** 把"读者此刻掌握了什么"当成一个**你显式管理的有限状态**：每讲完一段，明说"这一节你只需带走这三条"，后文**只**建立在这些之上。两个 skill 都没有这个概念，而它才是防止术语滚雪球的机制。
3. **指针式回引。** 后文要复用前文结论时，写"第 2 节 takeaway ③"这种**便宜的指针**——既不重述（啰嗦），也不假设读者背下来了（傲慢）。
4. **判断先行。** 读者提出一个断言时，第一句先给"对 / 不对"，再给事实，最后把他**真正担心的那件事**接住。
5. **单向收敛 + 跨消息更正的隔离。** 篇内绝不出现"先 A 后非 A"（读者已经把 A 记下来了，推翻它等于作废他对整篇的信任）；而**上一条消息**里讲歪的东西必须明说、且只在开头说一次。两个 skill 都只讲怎么把话说清楚，没讲**读者的模型是被你逐段写入的状态**——写入了就不能随手擦掉。见铁律 2。
6. **改动三件套。** 讲一个你做的改动：**原来卡在哪 → 改法（贴最小 diff）→ 现在的结果 + 改动量**。

## 3. 方法（两条铁律 + 六件事，每件带判据与反例）

### 铁律 1：动笔前先弄清他到底在问什么、在意什么

**读者写下来的那句话，不等于他要的东西。** 直接照着字面解释，是迎合的变种——省掉了"他可能问偏了"这个真实可能性，于是你答得越详细，离他真正的困惑越远。

动笔前先过三关（取自 `/no-flattering` 铁律一，这里是解释场景的用法）：

1. **理解校验**：把他的问题**复述成你的话**。复述不出来，说明你还不知道他问的是什么，先对齐。
2. **指代校验**：这句话指向上下文里**哪一个**具体对象？"这里为什么这么写"——哪个"这里"？候选项超过一个就先钉死。
3. **匹配校验 + 分维度**：他的问题**真的能问到他在意的那件事吗**？常见错配是：他问一个技术细节，真正担心的是"这样会不会出事"。这时**两个都要答**——先答他问的，再把他在意的接住，并明说这是两件事。

**判据**：写完之后回头看，能不能指出"他问的是 X，他在意的是 Y"。指不出来，说明你只是在应付字面。

**反例**：他问"这个值应该是相对 YAML 的吧？"——只回答"不是，是相对进程工作目录"就走人。他真正在意的是"那脚本还跑不跑得起来"，这个不接住，答案再准确也没解决他的问题。

**边界**：他判断对的时候，明确说他对，甚至对得比你深（`/no-flattering` 边界条）。校验不是为了找茬。

### 铁律 2：单向收敛 —— 收敛完再开口，篇内不许回头

**一篇解释里，任何事实只允许出现它的最终值。** 先说"漏了 19 条"、后面补一句"其实是 32 条"，是最严重的失败——不是啰嗦问题，是**摧毁读者已经建好的模型**：他把 19 记下来了，现在既不知道该信哪个，也不知道前面**别的**数字是不是也待修正。**读者对整篇的信任是一次性作废的，不是局部作废。**

三条具体要求：

1. **发现过程发生在动笔之前。** 事实要查完、数字要对完、结论要收敛完，然后才开始写。写到一半发现前面写错了 → **回去改前面**，不是在后面追加更正。
2. **全路径统一最终值。** 数字是 32 就**从第一次出现起就是 32**，正文、表格、推导、结论、每一处引用它的地方，**口径完全一致**。不存在"先给旧值、后面纠正"这种写法——旧值根本不该在正文里出现过。
3. **历史（被推翻的中间态）默认不提。** 处理方式按"读者是否已经持有那个值"分两种，**只有这两种**：

   | 情况 | 读者的状态 | 怎么办 |
   |---|---|---|
   | **他从未持有**（我自己工作过程中的中间态：第一版报告是 19、后来查出是 32） | 他脑子里没有 19 | **默认一个字都不提**。只有当他问了、或这段历史解释了某个**当前仍能看到的痕迹**时，才在**该段末尾或文末**放一行引用块：`> 历史上发生过修正：第一份报告是 19 条`。一行说完，不展开过程 |
   | **他已经持有**（我上一条消息告诉过他 A，现在确认是非 A） | 他脑子里有 A，会带着 A 往下读 | 在**开头**一行说清：`更正：我上次说的 X 应为 Y`。一次说完，此后全篇只用 Y |

   分界就是这一句：**读者从未持有的错误值，提它 = 平白无故在他脑子里种一个待作废的东西**；读者已经持有的错误值，不提 = 让他一直用错的模型。

**唯一例外**：解释对象**本身就是时间演变**（版本迁移史、事故时间线、"这个决定是怎么变的"）。这时候先后关系是内容，不是噪音——但要在开头就说明"本篇讲的是演变过程"，让读者知道他读到的中间态是**史料而非当前事实**。

- **判据一**：通篇搜"其实 / 实际上 / 不过 / 后来发现 / 更正 / 严格说"，凡是**否定本篇前文给出的值**的，一律违规。
- **判据二**：随便挑一个数字或结论，问"读者在读到它之后，还需不需要往后读才能知道它是不是最终值？"——需要，就是违规。
- **判据三**：把同一个量在全篇的所有出现处列出来（正文、表格、小结、结论），**必须字字一致**。出现两个值就是违规，哪怕后一个标了"更正"。
- **反例**（真实发生）：先写"遗漏了 19 条"，几段之后写"但后面发现其实漏了 32 条"。读者的正确反应是**不再相信这篇里的任何数字**。
- **正确写法**：全篇从头到尾都是 32；`19` 默认不出现；真有必要交代时，文末一行 `> 历史上发生过修正：第一份报告是 19 条`——**没人问就连这行也不写**。

### 3.1 从零建模：先给整体，再碰任何细节

在讲任何具体内容之前，用一段把读者领进现场：**这东西在系统里是什么角色、一辈子做哪几件事、它碰的关键概念各自是什么意思**。给这些角色**起可复用的短把手**（"门 A / 门 B"、"阶段一 / 阶段二"），后文靠把手指代，不靠术语。

- **判据**：读者读完这一段，后面每个名词都能挂到某个把手上。
- **反例**：直接从 `warn_work_dir_criteria_misuse` 开讲，指望读者从函数名里读出它是干嘛的。

### 3.2 每个专有名词就地绑回读者背景

第一次出现、以及**距上次出现较远时**，括号里立刻说清：**它是哪个子系统的什么东西、干什么用的**。

- 样板：``{{ work_dir }}``（一个占位符，作者可以写在 YAML 里，运行时被替换成一个真实路径）
- 样板：`evidence`（迁移门禁里那个字段，装的是 agent 自己写的一段说明）
- **判据**：把整篇里所有 `` ` `` 包起来的名词单独列出来，每一个都能在**紧挨它的括号里**找到"是什么 + 干啥"。找不到就是欠债。
- **反例**（本方法的来历，真实发生过）：写了"注册期 criteria 误用告警没覆盖 general_rules，`warn_work_dir_criteria_misuse` 只扫 `transition.guard.soft`"——三个名词、零个绑定，读者只能翻上文或放弃。

### 3.3 分段 takeaway 契约

每讲完一个自洽的段落，停下来写一个小结框：**"本节 takeaway（后面全靠这几条）"**，用编号列 2–4 条。往下的论述**只允许**建立在「读者原有背景 + 已声明的 takeaway」上。

- **判据**：随便挑后文一个论断，问它依赖的前提是否都在某条 takeaway 或读者原有背景里。若依赖了某个只在正文里一闪而过的事实 → 要么提升为 takeaway，要么就地重述。
- **注意**：takeaway 是**契约不是摘要**——不是"我说过什么"，而是"我接下来只会用这些"。

### 3.4 指针式回引

后文用到前文结论时，写"第 2 节 takeaway ③（占位符替换只对本包开放）"——**指针 + 一句话内容**。

- **判据**：读者不用往回翻就能继续读；同时也没被灌第二遍完整解释。

### 3.5 对照要写成"是什么 / 怎么用 / 我们对应什么"三列

做"我们 vs 既有"的对照时，表格第一列是名词，**第二列必须是"它是什么"**，第三列才是数据。只有名词和数据的表格，等于把 glossary 的活丢给读者。

- **加分项**：把"名义上有、实际没人读"这类**真相**标出来（例：某字段全仓只有可视化工具会读，运行期没有任何语义）。读者最需要的往往是这个。

### 3.6 讲改动用三件套，讲判断用判断先行

- **改动**：原来卡在哪（含"卡住会导致什么后果"）→ 改法（贴最小 diff，`-` / `+` 两行胜过一段话）→ 现在的结果 + 改动量（几个文件 / 几行）。
- **判断**：读者说"我觉得是 X 吧？"——**第一句给对错**，第二段给事实依据，第三段把他真正担心的那件事接住（往往他的结论错了但担心是对的，要明确告诉他担心不成立或成立在哪）。
  - 否定时要说清**错在哪一层**：是**前提**不成立（他以为的那个事实不存在），还是**推导**不成立（前提对，但推不出他的结论）。只丢"不对"等于没拷打。
  - 他对的时候**明确说他对**，别为了显得严谨而挑毛病。
- **自我更正**：发现**先前某条消息里**把某件事讲歪了，单起一段"我这句得更正"，说清原话哪里误导、正确的说法是什么。
  - **严格限定在跨消息**（铁律 2 第 3 条）：更正的对象只能是**上一条 / 更早消息**里的说法，且必须放在本篇**开头**、一次说完。
  - **篇内不适用**：同一篇里发现自己前面写错了，回去改掉，不是往后追加更正。

## 4. 输出骨架（按需裁剪，不必全套）

```
[他问的是 X / 他在意的是 Y]    ← 动笔前想清楚，未必写出来，但必须两个都答到
[跨消息更正 / 对方判断的对错]  ← 只放"读者已经持有的错误值"，一行说完
§0  从零建模 + 把手命名
    ↓ takeaway 契约（2–4 条）
§1  第一块内容（抽象点 → 紧跟具体例子）
    ↓ takeaway 契约
§2  第二块内容（指针回引 §1 takeaway）
    ↓ takeaway 契约
§3  对照 / 结论（三列表格；标出"名义字段"这类真相）
§4  分类收尾：已解决 / 有意不做（给理由）/ 真缺（给处理建议）
[> 历史补注]  ← 可选，默认不写；只有对方问了或它解释了当前仍可见的痕迹时才写，一行
[一个明确的问题，或一句"要不要我动手做 X"]
```

**正文里的每个值都是最终值**——历史（如果写）只能以补注形式出现在下方，不参与任何推导。

## 5. 失败模式

- **术语零绑定**：见 §3.2 反例。判据：`grep` 出所有反引号名词，逐个查有没有紧邻 gloss。
- **术语滚雪球**：第 3 节用第 2 节的名词、第 4 节用第 3 节的，读者的负债线性增长。解法就是 takeaway 契约。
- **表格当 glossary 用**：列名是术语、格子是数据、没有一列说"这是什么"。
- **压过头**：把三段压成一句"因为 X 所以 Y"，读者要自己展开。**判据：读者读完若要反问"具体啥意思 / 能举例吗"，就是压过头了**（pd-v2 §五 原话）。
- **展开过头**：每个名词都绑三遍、每段都有 takeaway，正文被脚手架淹没。**判据：一段里 gloss 超过两处、或 takeaway 条目超过四条，多半该合并。**
- **篇内自我推翻**（最严重）：先给一个值，后面又否定它。见铁律 2。判据：搜"其实 / 实际上 / 后来发现"，凡否定本篇前文的，一律违规。
- **边查边写**：一边探索一边输出，于是前半篇是中间态、后半篇是结论。**读者拿到的是你的工作过程，不是你的结论。** 解法是铁律 2 第 1 条：收敛完再动笔。
- **把返工写进解释**："本来打算 A，后来改成 B，又发现 B 有问题于是 C"——除非讲的就是演变史，否则读者只需要 C 和"为什么是 C"。
- **无人过问的历史**：没人问、也不解释任何当前痕迹的中间态，却因为"想说清来龙去脉"写进去。**读者从未持有的错误值，写出来等于凭空给他一个待作废的东西。** 默认删掉；真要留，压成文末一行引用块。
- **静默修正**：发现**上一条消息**讲错了，悄悄改口径不明说。读者会带着旧模型继续读，后面全错。（与上面相反的失败：篇内该改不改，跨消息该说不说。）
- **迎合式解释**：照着他的字面问题答，不校验他是不是问偏了。**答得越详细，离他真正的困惑越远。** 解法是铁律 1。
- **当转发人**：把别的 agent / 工具 / 检索结果的结论直接写进解释当事实。没自己验过就要标明"未验证"，多个来源一致也可能只是同源回声。
- **暴露方法论**：在解释里写"我按第几条在做 / 这一段是 takeaway 契约"。脚手架是给你自己用的，读者只该看到结果。
- **自证严谨**：把"我查了多少东西 / 跑了多少测试"写在前面。读者要的是结论和依据，不是你的工作量。
- **假设读者记得对话历史**：跨消息复用一个只在三条消息前定义过的名词，等同于零绑定。

## 7. 这个方法保证不了什么（诚实边界）

- **保证不了对方真的懂了。** 读者说"懂了"不等于懂——这和 pd-v2 §五末尾承认的是同一件事：唯一的检验是他能不能用这份理解做对下一件事，而那是**滞后的、外部的**。
- **保证不了篇幅。** takeaway 契约 + 就地绑定必然更长。对方要的是一句话时，这个 skill 是错的工具。
- **绑定的质量取决于你对读者背景的判断。** 判断错了（把他熟的东西反复绑、把他不熟的当常识），照样白讲。背景判断本身不在本 skill 的能力范围内——它只能保证"你认定他不熟的那些，你确实绑了"。
