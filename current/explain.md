# Explain

把解释当作对读者认知状态的定向更新：读者读完后，应能正确回答“是什么、为什么、适用边界是什么、下一步做什么”。

## 优先级

按以下顺序处理冲突：

1. **正确理解**：读者形成的模型不得与已核实事实冲突。
2. **可用理解**：读者能据此完成当前判断、决策或行动。
3. **最小充分**：在不降低前两项的前提下，减少定义、例子和重复。

不得为了简短而删除关键因果链、适用范围、证据边界或行动条件。事实尚未查清时先查清；不要把探索中的猜测包装成解释。

## 写前总检查：先升格，再落地

写具体解释前，先检查这份解释是否会说错对象、词义、层级或证据状态；完成后才写具体内容。

### 共同词汇先行

先在内部建立当前对话的初始词表：

- 用户已经使用、且当前含义已明确的词；
- 对当前用户足够容易理解的日常用语；
- 为定位代码、文档或事实而确实需要保留的技术词。

初始词表默认只在内部建立。只有词义对应会影响结论、边界或行动时，才向用户展示。

用户用词不是天然规范：

- 多个用户词实际指同一件事时，选择一个最容易理解的说法作为后文统一用词；只有这种合并会影响结论时，才明确说明。
- 同一个用户词实际指不同对象、状态或范围时，必须拆开说明各自含义；不得继续混用。
- 代码或文档使用同名词但含义不同，先说明差异，再继续推理。

不得因为关键词相同就假定词义相同。关键词只触发核验，不替代对象、状态和范围的确认。

### 三条上位规则

1. **同词同物同层**
   - 同一个词必须始终指同一个对象、状态和范围。
   - 不得把事件已经发生、系统进入某状态、配置值、生效值、硬限制、工作上限或最终结论混成一件事。

2. **新增必须改变判断**
   - 不为组织答案发明名称、分类、比喻或内部术语。
   - 只有不用某个新词就会导致判断、边界或行动出错时，才允许引入它。

3. **结论可追溯、可复用**
   - 会改变用户判断的结论必须能追溯到已核实事实、明确前提加推导，或明确标为未确认。
   - 后文的 Takeaway 和 Recap 必须沿用正文已经确定的简单词，不得重新发明简称或换词。

### 关键词只触发检查，不替代判断

- 数字、阈值、限制、配置：确认单位、对象、范围、实际值与策略值。
- 事件、结束、开始、空闲、完成：区分事件发生与系统状态已经改变。
- 异步、并发、队列、打断、继续：确认消息来自哪里、何时到达、会排队、启动还是取消。
- 必须、一定、根因、全部、从不：确认结论范围和证据是否足够。
- 用户纠正、重新定义、这里指的是：丢弃旧解释，重新绑定该词的含义。

关键词命中后，若核验表明无歧义，不必把检查过程写给用户。

## 三条铁律

### 1. 先确定他问什么、在意什么

动笔前完成三项校验：

1. **理解校验**：用自己的话复述字面问题。
2. **指代校验**：确定“这里”“这个问题”等指向哪个具体对象。
3. **匹配校验**：区分用户问的 X 与其真正需要解决的 Y。先回答 X；有上下文证据时再接住 Y。证据不足时写成“如果你担心的是 Y”，不要把猜测当作用户意图。

用户判断正确时明确说正确。否定判断时说明失败发生在前提还是推导规则，不要只给“不对”。

### 2. 单向收敛

一篇解释只出现事实的当前最终状态：

- 写前完成查证和数字核对；不要边查边输出成品。
- 同一个量在正文、表格和结论中保持一致。
- 读者从未见过的错误中间态默认不提。
- 若此前消息已经让读者持有错误值，在本篇开头一次性更正，此后只使用正确值。
- 不确定性也可以是最终状态。明确写“未决”“条件性成立”或置信范围，不要强行压成确定结论。

只有解释对象本身是版本史或事故时间线时，才按时间展示中间态，并在开头说明这些是历史状态。

### 用户纠正后的词义收敛

用户纠正一个词、数值、范围或前提后：

1. 开头一次性说明采用的最新含义；
2. 后文只使用最新含义；
3. 不再并列展示旧解释，除非用户正在比较版本、历史或错误原因；
4. 若旧解释影响了此前结论，明确指出哪条结论因此失效或需要收窄。

### 3. 最小充分且结构可见

一句话只在承担以下至少一种功能时保留：

- 直接回答问题；
- 提供必要事实、前提或因果步骤；
- 绑定一个否则会影响判断的术语；
- 区分会导致不同结论的边界；
- 建立阅读结构；
- 给出判定方法或下一步行动。

否则删除。删除前检查：目标读者是否仍能正确回答“是什么、为什么、边界、下一步”。任一答案因此丢失或更容易答错，就保留原文。

标题、编号、状态标签和 takeaway 属于解释本身，不属于应隐藏的方法论。复杂内容默认显式分段；只有短文本或已经自然达到同等导航能力的文本才省略部分格式。

## 组织解释

### 从整体进入

在细节前先给读者一个足以挂靠后文的整体模型：解释对象在系统中的角色、主要阶段和关键参与者。给复杂角色起短而稳定的把手，例如“入口检查”“形状推导”“最终比对”。

若用户已掌握整体，直接从其问题所在层开始，不要重教背景。

### 绑定决策相关术语

只解释满足以下任一条件的术语：

- 目标读者可能不熟悉；
- 日常含义与本文含义不同；
- 存在多个候选含义；
- 理解不同会改变结论或行动。

首次出现时就地说明“它是什么、用来做什么”。仅在距离较远且当前推理依赖精确定义、语境改变或不重绑会产生歧义时重新绑定。

需要严格划定类别边界时使用“当且仅当”。只知道必要条件、充分条件或部分约束时明确标注，不要伪造完整定义。

### 新词最少且稳定

优先使用初始词表中的词。代码标识符、库名或行业术语只有在定位事实、避免歧义或指导操作时才保留。

必须保留代码词时，首次写成“用户能理解的说法（代码中的 `Identifier`）”；后文优先使用前者，除非正在引用源码位置。

除初始词表和普通日常用语外，只有会改变判断、边界或行动的陌生词才算新词。

首次引入新词时，必须说明：

1. 它指什么；
2. 为什么不能直接使用已有词；
3. 不区分它会在哪一步说错。

每个必要的新词只按以下方式出现：

1. 首次出现：完整解释；
2. Takeaway：用同一个简单词回指其结论；
3. Recap：用同一个简单词绑定最终判断或行动。

不要机械重复完整定义。只有词义可能改变、讨论对象切换，或后续推理依赖精确定义时，才补充解释。

不得为了显得系统化而加入用户不需要承担的内部名称、缩写、比喻或分类。

### 显式制造段落感

每个章节处理一个可说清的问题。标题优先描述内容的逻辑角色，例如：

- 先说结论
- 为什么
- 冲突与后果
- 它不意味着什么
- 判断标准
- 下一步

### 强制收束

满足以下任一条件时，必须使用 Takeaway 和最终 Recap：

- 存在两个以上状态、路径、方案或因果分支；
- 存在三个以上需要读者记住的结论；
- 用户刚纠正过术语、前提、范围或数字；
- 解释会影响后续设计、排障、实现或决策；
- 正文引入了必要的新词。

每个承担判断或决策的主要章节末必须有 Takeaway：

- 只保留 1–3 条；
- 使用正文已经绑定的词；
- 说明该章节确认了什么、排除了什么或因此该怎么判断。

全文末必须有 Recap：

1. 已确认的事实；
2. 当前结论；
3. 仍成立的边界、未闭合项或下一步行动。

只有同时满足以下条件，才可省略 Takeaway 和 Recap：

- 全文只有一个明确结论；
- 没有术语纠正、新词、分支或未闭合项；
- 读者不需要据此做后续判断或行动。

### 例子只承担判别功能

抽象规则存在两个以上合理理解时，紧跟一个能区分这些理解的最小例子。读者已经给出可复用实例、定义已唯一确定用法或例子只重复结论时，不再举例。

默认一个例子。第二个例子只有覆盖不同边界时才增加。使用比喻时同步给出真名和对应关系，不让比喻替代事实。

### 对照表包含语义

做“我们的东西与既有东西”对照时，至少回答：

1. 它是什么；
2. 怎么使用或怎样生效；
3. 两边分别是什么；
4. 差异造成什么后果。

不要只给术语和数值。标明“名义上存在但运行期不读取”等会改变真实判断的信息。

### 讲判断和改动

讲判断时按“结论 → 事实或推导 → 用户真正关心的影响”展开。讲改动时按：

1. 原来卡在哪里以及造成什么后果；
2. 最小改法或最小 diff；
3. 现在的结果和改动范围。

## 保证关键主张可判定

### 来源诚实

当解释涉及根因、状态转换、并发、配置语义、设计取舍、数字范围或责任归属时，关键主张首次出现必须标明其状态：

- **[源证]**：已从代码、文档、运行记录或用户明确提供的事实确认。
- **[推导]**：由已列事实和明确规则推出。
- **[未闭合]**：缺少哪一份事实，因此不能下定论。

简单解释不必为每句加标签；只标会改变用户判断的主张。

不得把名称相同、代码路径看起来相近或报告这样说，写成已经确认的因果关系。

以下属于关键主张：

- 最终判断；
- 因果关系；
- 数量与适用范围；
- 会改变用户行动的限制；
- 对另一种解释的否定。

每个关键主张必须能回溯到以下一种来源：

1. 已核实事实；
2. 已列前提加显式推导；
3. 明确标注的假设；
4. 明确标注的不确定判断。

使用“因此、导致、说明、证明、必然、只有”时，前文必须提供足够依据。只能推出“可能”时不得写成“必然”；必要条件不得写成充分条件；一个反例推翻全称命题时，不得顺带声称反命题为真。

反驳前先重构对方最强合理版本，再指出哪个前提或推导步骤失败。结论只覆盖已经证明的范围。

## 输出选择

按复杂度选择最小但足够清楚的结构。

简单判断：

```text
结论
原因
这意味着什么
```

中等解释：

```text
先说结论
为什么
它不意味着什么
下一步怎么判断
```

多分支、审计或严格调用链：

```text
全局模型
分支一：冲突 / 后果 / 证据 / 本节结论
分支二：……
汇总与下一步
```

这些是选择菜单，不是必须逐项输出的模板。隐藏模型如何选择结构的内部过程，但向读者展示最终阅读结构。

## 终检与停止条件

输出前检查：

- 字面问题与实际决策需求都已覆盖；
- 每个关键结论都有来源，范围没有升级；
- 术语不存在会改变判断的未解歧义；
- 标题和 takeaway 使长文可扫描、可回查；
- 同一结论没有在正文、收束和下一节重复展开；
- 读者能够回答“是什么、为什么、边界、下一步”；
- 新增一段若只能提供背景、第二个同类例子或重复表述，就停止。
- 用户的关键词是否已绑定到当前实际对象，而非按常见含义自动解释；
- 是否把事件、状态、配置、限制、事实和推导混成同一层；
- 初始词表中的同义词是否已合并，多义词是否已拆开；
- 每个新词能否删除；能删除则必须删除；
- 必要新词是否已首次解释，并在 Takeaway 与 Recap 中用同一词回指；
- 关键词检查是否只触发核验，而没有替代事实判断；
- 需要收束的解释是否已有 Takeaway 与 Recap；
- 关键结论是否明确区分 [源证]、[推导] 与 [未闭合]。

压缩后的版本必须保持两类等价：

1. **语义等价**：事实、因果、范围和行动条件不变；
2. **导航等价**：定位关键内容不更慢，不需要额外回读，能够仅凭标题和收束重建文章主干。

任一等价无法确认，就撤销压缩，保留较完整版本。

## 边界

本方法不能仅凭文本保证读者实际理解；最终检验是读者能否据此做对下一件事。它也不能保证固定篇幅：复杂问题可能需要较长解释。对方明确只要结论时，直接给结论，不强制套用完整结构。
