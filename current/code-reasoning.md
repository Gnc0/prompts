# 代码 Bug 的问题意识驱动推理（code-bug-reasoning）

> 把一个 code bug **讲清楚 / 判真假 / 定可达性**的方法。它是 `principle-derivation-v2` 的**代码场景特化**——姿态（邀请、深入浅出、别惜墨、比喻配真名）**全部沿用 pd-v2**，`schema-matching-agent` 的六轴调节同样在背景运行；本文不复述，只加代码场景独有的三个机制。
>
> **双重身份**：它既是"怎么给人讲清一个 bug"的方法，也是**逐函数契约分析（verify-program / FM-Agent / CCodeAnalyze 那类 per-function Pre/Post + SP）结构性缺的那条边的规格**——见文末「§六 双重身份」。
>
> **一句话骨架**：**先建全局心智模型（补齐读者前置知识）→ 逐层走调用链（每层先大局定位再碰代码）→ 用契约传播找"击穿点"（后条件标异常 · 前条件标非-UB · 击穿即 bug）→ 条件合取 + 完整性论证 → 可达性裁定（真/假/条件/理论）→ 如实交代传播断点。**

---

# §零 用之前先问：读者的模型在哪

代码 bug 讲不清，**九成不是代码没讲透，是读者没有装那个 bug 的心智模型**。pd-v2 §四.3"先把读者领进全局"在代码场景是**硬起手**，不是可选润色。

**判据**：你要讲的东西里，只要有一个**领域概念**（这算子/服务/模块在干嘛、这些数据结构代表什么、这个字段的业务含义）读者可能不懂，你就**先从零把它讲出来**，再碰代码。读者一问"这在做什么 / 这个张量是啥 / 为什么要有这一步"，**不是他迟钝，是你跳过了建模——硬信号**。

# §一 核心机制 1：大局先行 + 逐层定位（治"惜墨"与"假设读者懂领域"）

## 1.1 开场：从零搭全局心智模型

在任何代码之前，先用一段**不预设领域知识**地讲清：

1. **这东西在整个系统里是什么角色**——它消费谁、产出给谁、在整条流水线的哪一环。
2. **它一辈子做的几件事**（把主流程压成 2–5 步的骨架）。
3. **它碰的关键数据/概念，逐个从零解释含义**（不是类型，是**语义**：这个数组代表什么、这个字段业务上意味着什么、它们之间的关键关系是什么）。**这些关系里，往往就藏着后面 bug 的心脏**——提前点名。
4. **一张地图**：把"几件事"画成调用骨架，**把要讲的 bug 标在地图上哪一步**。

> 具体例（稀疏注意力反向的排班算子）：先讲"它不算注意力、是个**排班员**：读规模信息→按规模把活分给各核→把排班表写进 metadata"；再从零讲"query/key、变长序列、seqused、稀疏 top-k"；**提前点名关键关系**"共有 Σseqused_q 个 query 行，topk 数组必须每行一条 → 长度 ≥ 总行数"——这条关系就是后面校验闸 bug 的心脏。

## 1.2 逐层：每层三段式

沿调用链一层层降。**每一层严格三段，顺序不能反**：

1. **大局定位（先）**：这一层在"几件事"里是哪件？关心什么？**为什么重要**（尤其：它和要讲的 bug 什么关系）？
2. **代码（中）**：钉**行号**、贴**关键几行**（不是整函数，是数据流上和 bug 相关的那几行）。
3. **回指大局（后）**：所以这段代码 = 大局里的哪个动作；把局部变量翻回业务语义（`sumOfQuerySeq` = "总 query 行数" = "排班表要多少座位"）。

**别惜墨**（pd-v2 §五"过度压缩=把展开成本甩给读者"）：该展开处全展开，不留"读者自行脑补"的缺口。判据：读者读完若要反问"具体啥意思 / 能举例吗"，就是压过头了。**惜墨在代码讲解里的典型后果 = loophole**：读者带着没建好的模型往下走，后面全塌。

# §二 核心机制 2：调用链契约传播（治"误报"与"漏报"，是找 bug 的引擎）

## 2.1 为什么需要它：有节点，无边

逐函数分析给你**节点**（每个函数的 Pre/Post）。但**大量真 bug 是"边"上涌现的**——A 函数产出一个异常值，顺数据流流到 B 函数，击穿了 B 的某个安全假设。**孤立看每个函数都对，组合起来才炸。** 只做逐函数契约 = 有节点无边 = **系统性漏掉跨函数涌现 bug**。

> 实证（这套方法的来历）：一次真实的逐函数语义分析 run，为 `GetSumOfQuerySeq` 写了 Post、也把某内存前置标成"尺寸依赖"，**但没连那条边**——`GetSumOfQuerySeq` 的 int32 返回值会**溢出成负**、流进那道尺寸检查、把它反转成真空放行。逐函数分析节点齐全却漏了这条边；是端到端的 PBT（天然跨函数）把它抓出来的。**本机制就是把这条边变成机械步骤。**

## 2.2 两种标注

**① 后条件（每函数，带【异常标注】）**：这个函数返回什么，**且在什么输入条件下返回一个【异常值】**——错值 / 负数 / 回卷 / 下溢 / 溢出 / 空指针 / 越界索引。异常标注是重点，普通 Post 只是陪衬。

```
GetSumOfQuerySeq 后条件：返回 Q（总行数）当 Q ≤ 2³¹−1；
                        〔异常〕否则 int32 回卷 Q−2³² < 0
```

**② 前条件（每【危险操作】，＝非-UB / 结果正确的条件）**：数组下标、除法、减法、乘法、解引用、类型窄化……每个危险操作，写下"要不 UB、要结果对，它**需要**输入满足什么"。

```
oriTopkPtr[bsStride] 前条件：0 ≤ bsStride < 数组元素数
former - 1（uint32）前条件：former ≥ 1   （否则 0−1 回卷成 UINT32_MAX）
a / b 前条件：b ≠ 0
```

## 2.3 双向传播 + 击穿点 = bug

- **前向**：把每个函数的**异常后条件**沿数据流往下带——这个异常值流到哪了？
- **后向**：把每个**危险操作的安全前条件**沿数据流往上问——谁负责保证它？保证得住吗？沿调用链一层层追那个"保证"。
- **bug 的定义 = 击穿点**：**某个危险操作的安全前条件，被上游某个异常后条件违反的那个点。** 即"保证"链上有个洞。

## 2.4 符号枚举表：治误报 + 漏报的机械化

**这一步是把"边界覆盖"从靠灵感变成机械枚举**，也是防止两类错的关键：

- **误报**：脑补"某操作数一异常，检查就废"——**没写另一个操作数的后条件**，高估了危险。
- **漏报**：只传播一个操作数的异常——**漏掉另一操作数也异常时所要求的额外条件**。

**做法**：凡涉及比较 / 运算的**多个操作数**，把**每个操作数的后条件（含异常分支）都写下**，然后**枚举所有异常组合**，逐格判后果。

> 具体例（校验闸 `oriTopkLengthSize < sumOfQuerySeq`，两操作数都 int32 会回卷）：

| 操作数 S 符号 | 操作数 Q 符号 | 触发条件 | 判决 | 后果 |
|---|---|---|---|---|
| 正 | 正 | 都 ≤21亿 | 真实比较 | 正常 ✓ |
| **负** | **负** | 都 >21亿（well-formed 大负载，S≈Q 同回卷）| ≈真实 | 其实对 ✓ ← 若只看 Q 会**误报**成"废" |
| **正** | **负** | Q>21亿 且 S≤21亿（欠配）| 正<负=假=放行 | **失效→bug** ← 只传 Q 会**漏掉** "S≤21亿" 这个必要条件 |
| 负 | 正 | S>21亿 且 Q≤21亿 | 真=拦 | 无害误拦 |

**四格一摊——误报当场纠、漏掉的必要条件当场逼出来。** 不靠"想到了"。

# §三 核心机制 3：可达性裁定（定真假 live）

一条 bug 光"链闭合"不够，还要问**触发输入在合理运行下达不达得到**。**两道关**：

1. **链闭合了吗**：从异常源 → 击穿点 → 真正的危险指令（内存访问 / 崩溃 / 错值落盘），**中间无"然后就出事了"的跳步**。（机制 2 保证。）
2. **触发输入合理可达吗**：把击穿所需的**全部条件列成合取 C1∧C2∧…**，逐条判现实可达。

**分级**：

| 级 | 判据 |
|---|---|
| **真·live** | 链闭合 + 触发输入在正常运行合理可达 |
| **真·条件性** | 链闭合 + 需异常/极端/畸形输入的合取（每条真缺陷、但非正常负载必犯）|
| **真·退化输入** | 链闭合 + 需退化输入（空/零/边界），正常不发但能穿过校验 |
| **理论** | 链闭合 + 触发需**不可能规模**（如 >43 亿元素、撞内存墙）|
| **假·不可达** | 链**不闭合**，或触发输入在唯一调用点结构性不可达（如 witness 的参数值该处永不出现）|

**几条锋利的判据（防自欺）**：

- **校验闸的威胁模型**：一道**输入校验**能被绕过，"需要畸形输入"**不算缓解**——畸形输入正是它存在的理由。真正门槛是**规模/前提**能不能达到。
- **witness ≠ 可达**：PBT/单测复现到一个 witness，**不等于该 witness 的参数值在真实调用点会出现**。必回到唯一调用点核参数的真实取值范围（如 `CeilDiv(2, 43亿)` 复现了，但真实调用 rnd 永远是 ~36 的核数 → 不可达 → 假）。
- **假兜底**：一个 early-out / guard 看着像处理了某情形，但它 `return true` / 没建立下游需要的前条件 → **没真兜住**。契约视角：它没转达安全前条件。
- **契约断在项目边界**：击穿点的后果落在**未见的下游消费者**（不在被分析代码里）→ 诚实裁定"缺陷确凿、危害悬于下游"，**不硬下"高危"或"无害"**。

# §四 输出结构（把三个机制串成一份 bug 说明）

1. **大局**（§一.1）：全局心智模型 + 前置概念 + 地图（bug 标在图上）。
2. **逐层调用链**（§一.2）：每层三段（大局定位 → 代码钉行号 → 回指大局），走到危险指令。
3. **契约 / 符号枚举**（§二）：关键函数的后条件（含异常标注）+ 危险操作的前条件 + 击穿点 + 多操作数时的符号枚举表。
4. **必要条件合取 + 完整性论证**（§三.2）：C1∧…∧Cn，每条钉代码依据；论证"沿数据流唯一路径穷尽了每个分叉"。
5. **可达性裁定**（§三）：分级 + 判据。
6. **残余传播断点**（§五）：**契约传到哪、可信到哪；没传到的地方如实列**——这是潜在漏报的暴露面，不许藏。

---

# §五 反模式（都踩过）

- **惜墨如金 → loophole**：读者缺模型时给一句话，理解成本全甩给读者。补：§零 + §一，别省建模。
- **假设读者懂领域**：直接从张量/业务术语讲起。补：§零硬起手。
- **误报（单操作数脑补）**：只看一个操作数异常就断言检查废。补：§二.4 符号枚举。
- **漏报（不传异常）**：某函数能产异常值却没往下游传。补：§二.3 前向传播。
- **witness 当可达**：复现到就说是 live。补：§三 回唯一调用点核参数范围。
- **假兜底当真兜底**：见 `return true` 的 early-out 就以为处理了。补：§三 契约视角查它转达了什么前条件。
- **契约断在边界还硬下结论**：下游没见到就断言高危/无害。补：§三 诚实标"悬于下游"。
- **残余断点藏起来**：只报闭合的、不报没传完的。补：§四.6 必列暴露面。

# §六 双重身份：它也是 per-function 分析缺的那条边

逐函数契约分析（verify-program 的 top-down demand + 逐函数 Pre/Post、FM-Agent 的 block-SP、CCodeAnalyze 的逐函数 SP）**擅长节点、结构性缺边**：函数内 carry-forward 传事实、caller→callee 传 demand，但**没有"跨函数异常传播"这个 pass**——一个函数产出的异常值流到另一函数击穿其前条件，这条边没人走。

**本方法的机制 2（§二）就是这条边的规格。** 因此可作为一个**独立 pass 反哺**那类分析：在逐函数 SP 之上，加一步"给每个函数 Post 标异常分支 → 沿 callgraph 数据流前向传播异常 / 后向传播危险操作的安全前条件 → 报击穿点"。**这比"给某个溢出加一句 caveat"的创可贴根治**——创可贴治一个点，这个 pass 补的是结构缺口。

# §七 何时用 / 不用

**用**：给人讲清一个 code bug；判一条疑似 bug 的真假与可达性；在逐函数分析后补跨函数涌现 bug 的 pass；审"整数溢出/下溢、越界、空指针、UB、校验被绕过"这类沿数据流传播的缺陷。

**不用**：纯语法/编译错（直接指）；读者已是该代码作者、只想要一行结论（别把结论藏进过程，pd-v2 §六）；单函数内的显然笔误（§二的跨函数机器过重）；bug 尚未定位、还在大海捞针阶段（先定位，本方法是"已锁定嫌疑段后如何讲清+判真假"）。
