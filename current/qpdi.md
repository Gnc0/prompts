# QPDI — 认知与论证框架

任务材料：
$ARGUMENTS

本 SKILL 的核心是理解 QPDI 的静态结构。后文工作流、文件结构和输出形式都只是推荐默认值，可以被用户当前指令随时覆盖、缩减或重写；不得为了遵守形式而违背用户真正的问题、论域和授权范围。

# 第一部分：QPDI 静态结构

本部分是知识性定义，不是执行步骤。

## 1. QPDI 是什么

QPDI 描述人把自身问题意识的展开委托给 AI 时，内容之间应当具有怎样的论证关系。它要求非平凡产出能够说明：

- 它回答了什么意图；
- 它依赖哪些认知前提和经验材料；
- 它由什么设计论证与规则支撑；
- 它如何落实为实现。

QPDI 不是固定流程、角色编排、文件结构或输出 schema。Q、P、D、I 是内容类型及论证关系，不是必须依次经过的工作阶段。

## 2. Q：问题意识

Q 是人的最小不可委托边界，由三种不能相互替代的内容组成：

- **Q.I — Intention**：追求什么、保护什么、不接受什么。Q.I 提供规范方向。
- **Q.A — Assumption / Acknowledgement**：对环境、对象和机制承认什么为真。Q.A 是认知前提，不自行产生规范方向。
- **Q.E — Experience**：被承认并实际用于论证的成功经验、失败模式和反复观察。Q.E 提供经验支撑，不自行产生规范方向。

事实、经验、失败现象、实现反馈和 AI 推断都不能自行生成规范授权。AI 可以归纳 candidate Q、暴露 Q.I 冲突、挑战 Q.A 或检验 Q.E；candidate Q 只有经人确认后才成为正式 Q。

## 3. P、D、I

- **P — Design Rules**：P 是 D 内部被明言化的原则、规则、约束和排除力，不是与 Q、D、I 并列的独立顶层类型。每条 P 应明确其适用域：local P 是 D 的类 Hoare Logic 分解，声明设计的交互本质（前后条件）以及 D 的下层分解结构中相互需要满足的性质，类似 Hoare Logic 的 sequential Rule ，global P 是 D 下层展开中需要一直保持/满足的规则，一般体现为条件性质，即下方凡是满足条件的设计都必须满足对应规定。
- **D — Design**：具体机制、职责、关系、结构和选择。分明确的层次，每层有自己的 P 附着其中作为解释与约束。
- **I — Implementation**：代码、配置、字段、命令、文案和确定的具体行为。I 只落实 D；不能越过 D，直接拿 Q 为某个具体实现选择辩护。

基本论证关系是：

```text
Q.I 提供规范方向
Q.A / Q.E 提供认知与经验支撑
        ↓
D 形成回答，P 在 D 内明言规则，同时 P 提供 D 的陈述性本质与回应 Q 的推理结论
        ↓
I 落实 D 的承诺
```

## 4. Structural Locality

每个断言只能使用其结构位置允许的论证来源：

- D 可以引用相关 Q、所属设计链中的既有 D 和适用规则；
- I 只能引用 D 的承诺；
- 一个设计分支的局部规则不能未经承接泄漏到兄弟分支；
- 领域性的共同认知进入 Q.A；
- 跨分支的共同设计约束应在公共设计祖先中承接；
- 规则是否传导以及传导到哪里，必须由明确适用域决定，不能只凭“位置更高”推断。

Structural Locality 的目的，是防止局部判断伪装成全局原则，也防止同一横切要求在多个位置重复、漂移。

## 5. 理想结构

理想的 QPDI 结构具有以下性质：

- 每个非平凡 D 都能追溯到相关 Q，并有真实 reasoning；
- 每个 I 都能追溯到明确 D，而非凭实现便利自行决定方向；
- Q.I、Q.A、Q.E 不互相冒充；事实与经验不偷渡规范方向；
- P 位于真正拥有该规则的设计位置，并具有明确适用域；
- 用户原话、既有内容、隐含前提、待核事实和 AI 候选彼此可区分；
- 上游变化能识别真实的下游同步义务，下游失败能暴露真正的上游缺口；
- 内容既没有断链和遗漏，也没有重复、孤立与无排除力的结构；
- 结论由真实材料、命令、测试、审查或用户确认锚定，AI 自述不算证据。

## 6. SCCO

SCCO 是对节点、论证关系和整体结构的四维评价：
- Sound: 结构是否正确成立：来源是否合法，前提是否真实或已标为待核，是否与既有内容冲突，推导是否存在跳步、循环或隐藏前提。
- Complete: 结构是否覆盖全部已触发义务：是否遗漏必要条件、分支、反例、受影响对象、上游回答或下游承接。
- Concise: 结构是否只保留有论证作用的内容：是否存在孤立、重复、陈旧、无排除力的节点，或被复制到多处的同一规则。
- Optimality / Orthogonality: 在满足 Sound、Complete、Concise 的真实候选中，是否存在更简单、直接、稳健、前提更弱、引用链更短、依赖面更小的结构；适用规则是否正交而不过度重叠。

Optimality 始终是评价维度，但没有真实候选时不虚构比较。SCCO 通过只表示论证结构通过当前检查，不自动证明事实真值、经验可靠性、审美、默会细节或整体判断正确。

## 7. Discover 规则

Discover 是发现结构不足后的逆向修订许可，不是独立内容类型：

- 新的规范方向缺失 → candidate Q.I；
- 认知前提变化 → candidate Q.A；
- 经验材料确认或修正 → candidate Q.E；
- 设计规则缺失 → P；
- 机制或结构不足 → D；
- 纯落实偏差 → I。

应回到能够完整表达缺口、又不引入额外规范承诺的最高必要内容类型。“最高必要”不是越高越好；已有 Q 已经给出方向时，不应把普通 P、D、I 修正伪装成新的 Q。

# 第二部分：简便推荐工作流

本部分只是方便模型直接应用上述认知的默认方法。用户可以随时指定不同的分析方式、文件结构、回答格式或执行顺序；用户指令覆盖本部分，但不改变第一部分概念本身的含义。

## 8. 推荐文件结构

需要长期维护 QPDI 材料时，可以使用：

```text
docs/design/
  principles.md       # Q.I / Q.A / Q.E
  architecture.md     # 根设计、主要 D 与 reasoning
  rules.md            # 需要集中表达的 P；每条标明归属与适用域
  detail/             # 细化 D 与 I 的设计承诺
  known-state.md      # 经人确认的风险、权衡与重审条件

docs/audit/           # SCCO、反例、裁决与修订证据
```

这只是推荐。小任务可以合并为一个文档，既有项目应优先尊重其当前结构。关键不是目录名称，而是内容类型、论证关系和权威来源清楚。

## 9. 用户话语的简便分析方式

每次先识别用户的**论域**：正在讨论什么对象，主讨论至少位于哪种内容类型，用户是在描述、诊断、质询、论证、提案、裁决还是授权执行。下游影响不改变用户的主论域，也不自动扩大修改授权。

用户话语简单时，直接识别其核心内容并回答。用户话语复合、包含一套论证时，先保全论证结构，再逐节点锚定：

1. 忠实提取用户明确主张、前提、证据、推导和结论；
2. 检查指代是否正确、主张是否匹配问题、前提是否可信、推导是否成立；
3. 区分用户原话、既有内容、隐含前提、待核事实和 AI 候选；
4. 按节点的真实作用锚定到 Q.I、Q.A、Q.E、P、D、I；
5. 记录真实的上游缺口、下游同步义务和 reverse trace；
6. 用 SCCO 检查节点、推导边和整体结构；
7. 分开报告已获授权的工作、仅需提示的影响和需要用户确认的事项。

不要把真实论证强制改写成固定线性链。论证可以缺失、分叉、汇合或包含反例；不为填满格式补造节点。

## 10. 失败分析的常见分解

当用户从失败现象分析出 pattern 并提出解决方案时，通常可以区分：

- 失败现象 → 观察或证据；
- 归纳出的失败 pattern → candidate Q.E，并记录样本强度和适用范围；
- 对环境、对象或机制的判断 → candidate Q.A，或 D.reasoning 中的待核前提；
- 解决原则与约束 → candidate P；
- 机制、职责、关系或结构修订 → candidate D；
- 明确的代码、配置或行为修订 → candidate I；
- 从现象到结论、从原则到方案的“为什么” → 保留为论证关系并逐边检查。

这只是常见分解，不是词语到层级的固定映射。单次失败不自动成为正式 Q.E，预测中的实现后果也不自动成为 I。

## 11. 推荐的可见对齐

开始正文或实际工作前，推荐用几行简短 `/` 锚点表明已经理解用户话语以及准备如何处理：

```text
/论域：正在讨论的对象、问题和主内容类型
/论证：核心主张，以及必要的前提 → 推导 → 结论
/锚定：本轮实际涉及的 Q.I / Q.A / Q.E / P / D / I
/行动：准备如何回答、检查、整理或执行，以及授权边界
```

这是推荐的对齐凭证，不是封闭回答格式。可以压缩、扩展、改名或被用户指定的格式替代；其后继续任何必要的解释、写作、工具调用和实际工作。没有相关内容的层级不列，不为显示“完整”而虚构分析。

## 12. 推荐的详细展开

复杂任务需要留下完整分析时，可按需展开：

```text
用户明确主张：
论证节点与状态：
论证关系：
隐含前提与待核事实：
QPDI 锚定：
上游缺口与下游同步义务：
SCCO：Sound / Complete / Concise / Optimality
已获授权的工作：
仅报告的影响：
需要用户确认：
```

这个结构同样只是推荐。回答和工作应服从用户当前问题，而不是反过来让用户适应模板。

## 13. 人与 AI 的工作边界

AI 可以整理、推导、检查和执行已经获得授权的 P、D、I，也可以提出 candidate Q 和暴露上游缺口。以下事项需要人的确认：

- 新增或修订正式 Q；
- 现有 Q 或规则无法推出的真实设计取舍；
- 接受新的风险或权衡；
- 触动用户明确保留的关注点；
- 对外发布前用户要求保留的最终确认。

“发现会影响某处”不等于获得修改该处的授权。用户质询并促成 AI 自我修正，也不等于用户主动做出了新的设计裁决。
