# SCCO Recall — 召回扇出（只捞不判）

审查对象：
$ARGUMENTS

未指定对象时，取当前分支相对基线的 diff（`git diff <base>...HEAD` + 未提交改动）；对象不明确先问清"审什么、边界到哪"再开始。

本 skill 自包含，可独立使用；更常见的位置是作 `/qpdi-tribunal` 或 `/hoare-audit` 的召回前端。

---

## 一、定位：体系的召回层，不是新维度

**出处与实证**：本方法从 max-recall code-review 方法论抽出。一次真实 PR 审查中，目标代码的引擎核已被 5 轮 spec 锚定 + disprove-first 审计（/hoare-audit 型）收敛，本方法一轮仍捞出 15 条有效发现——其中最值钱的两条（可视化器把仅由新字段门禁的状态谎报为"无约束"、审计日志丢结构化遥测）都在 **PR 未改动、但被它影响的消费者代码**里。

把它的 10 个镜头投影回 SCCO：

| 镜头 | SCCO 归属 |
|---|---|
| 逐行 / 删除行为 / 跨文件消费者 / 语言坑 / 包装转发 | **S**（正确性，拆 5 路）|
| 约定合规（CLAUDE.md / 项目规约）| **S**（对规则层的 Sound——约定就是要求，要求就是 spec 的一部分）|
| 复用 / 简化 | **C-Concise** |
| 效率 / 高度 | **O** |

**零个新维度。** 它比 freeform 的"检查 SCCO"召回率高，靠的是三样 SCCO 写了轴、但没建的东西：

1. **召回程序**：把一个维度（尤其 S）拆成 N 个互盲、正交、低阈值的并行子搜索——同一根轴，配一套高召回的搜法。
2. **召回/精度分层**：捞的 agent 只管捞，砍的 agent 只管砍。动机相反的两件事混在一个 agent 里，"要论得成立"的动机会压低召回。
3. **范围规则**：审查边界 = 目标产物 **+ 被它影响的消费者**（强制角度）。盯着"目标产物"的审查天然不会走出去。

**与兄弟 skill 的分工**：本 skill = 召回层（产候选池）；`/qpdi-tribunal` = 判断层（counter→judge + 分流"可修 / 需裁决 / 伪问题"）；`/hoare-audit` = 重型判断层（spec 门 + ≥2 disprove-first challenger + 收敛循环 + 每条确认发现钉 PBT）。tribunal 与 hoare-audit 都可以把本 skill 当召回前端调用——召回层只该有一份，不在每个判断 skill 里各造一套。

## 二、三条结构原则

1. **只捞不判（召回纯度）**
   - finder 的任务词写明"宁滥勿缺、发现即报"；禁止 finder 自我过滤"这可能是有意的"。
   - finder **spec-盲**：不给设计文档的"已知限制 / 有意不做"段。代价是会捞到有意决策（实证：某候选对应的代码注释里明写 "ignored"，是登记过的设计决策）——**过滤这类噪音是精度层拿着 spec 的职责。spec 门在判断层，不在召回层**。两层各自纯粹，好过一层里互相污染。
2. **正交盲扇出**
   - 镜头互盲：任何 finder 看不到其他 finder 的产出；一个镜头的结论不许压制另一个。
   - 每镜头封顶（如 ≤8 条），防单镜头刷屏；两个镜头因不同理由撞同一行 → 记两条，去重是聚合者的事。
   - 每候选必须带**具体触发场景**（什么输入/状态/时机 → 什么错误结果/成本）；"可能有问题"不算候选。
3. **消费者范围扩张（强制镜头）**
   - 对每个被改的符号 / schema / 契约，Grep 全库找消费者（渲染器、日志/遥测、下游调用方、跨模块镜像、序列化对端），检查**目标没改但被影响**的代码。
   - 这是唯一一条"审什么"的边界新规则，也是实证中产出密度最高的一条。

## 三、镜头菜单（按 SCCO 维度选配）

**代码 diff 类对象**：

| 维度 | 镜头 | 各自问什么 |
|---|---|---|
| S | 逐行扫描 | 每行：什么输入/状态/时机/平台让这行错？（条件反转、off-by-one、错变量复制粘贴、吞错）|
| S | 删除行为 | 每条被删/被替换的行原来维持什么不变量？新代码在哪重建了它？找不到 = 候选 |
| S | **跨文件消费者（强制）** | 被改函数/字段的所有 caller/consumer 还成立吗？渲染、日志、wire 对端、测试夹具跟上了吗？ |
| S | 语言坑 | 本语言/框架经典坑（如 Rust：unwrap 可达性、serde default/flatten/枚举、char boundary、async 超时语义、env unsafe）|
| S | 包装/转发 | wrapper/adapter 每个方法都路由到被包装体？没有绕回全局/注册表？转发面覆盖 caller 实际用到的全部方法？ |
| S | 规则层合规 | 找 governing 约定文件（CLAUDE.md 等），只报"能引规则原文 + 能引违规行"的违规——约定即要求 |
| C-Concise | 复用 | 新代码重实现了库里已有的东西？点名该调用的现成 helper |
| C-Concise | 简化 | 冗余/可导出状态、复制粘贴微变体、死代码、双份逻辑；点名等价的更简形式 |
| O | 效率 | 热路径重复计算/重复 I/O、每调用重编译/重克隆、可合批的串行；点名更省的替代 + 路径频度 |
| O | 高度 | 修在正确深度吗？共享设施上叠特例 = 修得不够深；点名更深的一般化形式 |

**设计文档 / 计划类对象**，同构换镜头：逐段论证（S）、删改承诺追踪——被改掉的承诺在哪重建（S）、**交叉引用消费者——引用本文档的其它文档/代码是否随之失效（S，强制）**、术语/事实漂移（S）、重复表达/陈旧残留（C-Concise）、更简组织（O）。

## 四、运行

```text
0 定标 → 1 选镜头 → 2 并行盲扇出 → 3 去重合并 → 4 移交精度层 → 5 缺口清扫
```

- **0 定标**：范围（diff 基线 / 文档清单）+ **部署上下文校准**（执行模型 / 信任边界 / 攻击者控制什么 / 持久化与并发模型——finder 用它判断"什么触发场景算现实"，此项借自 /hoare-audit Step 1a）。
- **1 选镜头**：按对象类型从菜单选配（可增删自创），消费者镜头必选。
- **2 并行盲扇出**：全部镜头**一次性并发**派出（fresh context sub-agent）；派遣词 = 角色 + 范围 + 部署上下文，**绝不灌预期结论**；产物统一 `{位置, SCCO 维度, summary, 触发场景}`。
- **3 去重合并**：同行同机制合并，保留触发场景最具体的一条；不同机制撞同行保留两条。
- **4 移交精度层**：见 §五。
- **5 缺口清扫**：一个 fresh finder 拿着已验证清单重读对象，**只找清单外的新缺陷**——重点是第一遍容易漏的二线坑（搬移代码丢守卫、谓词带副作用、测试 setup/teardown 不对称、默认值翻转）。没有就交空，不许凑数。

## 五、移交档位（召回之后谁来判）

| 档 | 机制 | 适用 |
|---|---|---|
| 轻 | 每候选派 1 个 verifier 三态判（CONFIRMED / PLAUSIBLE / REFUTED；非 REFUTED 即保留） | 低风险、要快。**诚实声明**：单票 verify 不是 disprove-first——verifier 没被命令"弄死这条"，对微妙 claim 的精度靠 verifier 自觉，不是结构保证。verifier 的正业除判真假外还包括**收窄触发条件**（实证：一条候选经 verify 从"任意两规则"收窄到"前序软拒 + 后续 script 动作"才成立）|
| 重 | 交 `/qpdi-tribunal` 的 counter→judge（**附 spec / 已登记决策**做过滤依据），产出分流：可直接修 / 需用户裁决 / 伪问题 | 对外交付前；发现将触发返工/裁决 |
| 最重 | 交 `/hoare-audit`：spec 门 + ≥2 disprove-first challenger + counter-challenger + 收敛循环 + 每条确认发现钉 PBT/回归测试 | 正确性关键代码；要收敛到不动点 |

**硬规则：本 skill 的产出是候选池，不是结论。** 未经精度层的候选不得当发现对外报告；报告里必须声明所用移交档位。

## 六、何时不用

- 改动很小（一眼能读完）→ 直接审，扇出是纯开销。
- 只想验证"代码 vs spec 一致性"且 spec 很强 → 直接 `/hoare-audit`。
- 对象还没成形（草稿共创中）→ 都不用，先把东西做出来。

## 七、相关 skill

- `/qpdi-tribunal` — 判断层：counter→judge 对抗式精度 + SCCO 分流。本 skill 的默认下游。
- `/hoare-audit` — 重型判断层：spec 门 + disprove-first 收敛 + PBT 钉死。可把本 skill 当其 Step 2 的召回前端。
- `/qpdi` — 宪政式全流程框架；本 skill 服务其审查关卡的召回半场。
- `/code-reasoning`（code-bug-reasoning）— 单条已锁定 code bug 的"讲清 + 判真假"；候选池里某条特别微妙时可对该条单独调用。
